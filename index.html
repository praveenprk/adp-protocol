The scenario

A bank changes its fee calculation with an AI agent

The payments team asks a coding agent to fix a rounding error in card fees, under change ticket CHG-4821. Before the change ships, an auditor asks four questions. This is how well ADP answers each one today.

Who approved this work?

Partly

A grant carries a human-signed approval as its root (ADP-2 G-6), and approval, merge and rulings can never be handed to an agent. A grant missing any limiting field is now rejected (G-10). The signature algorithm is deliberately left for later, so the signature must be present but is not yet checked cryptographically.

How much freedom did the agent have?

Partly

The grant names what the agent may read and write, for one session only (G-3, G-4, G-8). Path matching is now defined exactly, so every tool gives the same answer on whether src/fees/round.py is in scope. What is missing is software that enforces it.

Could the agent change its own controls?

Partly

No grant may let an agent write to its own guardrails: CI, hooks, grant storage (G-7). The overlap test is now defined and errs toward refusing, and a path like src/../ci/hook matches nothing. Enforcement on disk is the runtime's job, and no runtime exists yet.

Can all of this be proven afterwards?

Not yet

The instruction, the grant and the human-signed repository record can each be checked by machine against published test cases, so the paperwork is solid. Proving what the agent actually did needs a runtime and a validator, and neither exists yet.

What each merge changed

Newest first. Proposal-only merges (#7–#10, #13, #15, #19) recorded decisions and are folded into the change that applied them.

#202026-11-17

Every authority check has one exact answer (ADP-2 2.0.0)

Path matching, the guardrail overlap test and how a grant is named in an instruction are now defined exactly. The human-signed record for creating or deleting a repository has a format and its own check. A grant missing a limiting field, or with an expiry outside UTC, is rejected. Five ADP-2 defects closed; ADP-2 has none open. Proposed and accepted in #19.

For the bank: two vendors' tools now give the same verdict on the CHG-4821 grant: src/fees/round.py is in scope, src/../ci/hook is refused, and a grant that forgets its protected list is rejected instead of silently allowing everything. Archiving the old fees repository needs a signed record naming exactly that one repository.

#182026-11-16

Known gaps written down

Eight gaps found while building ADP-2 were filed with evidence, and a brittle CI test was fixed.

For the bank: the auditor gets a register of every known weakness, with proof, instead of a claim that everything is fine.

#172026-11-16

Who may ask an agent to do what (ADP-2)

Grants: approval-rooted, session-bound permissions. Creating or deleting a repository needs a human signature scaled to risk. Approval and merge stay human.

For the bank: the change manager issues a grant for CHG-4821: read docs/**, write src/fees/**, today only, with CI and hooks protected. An instruction outside that scope is refused, and the agent cannot open a public repository on its own.

#162026-11-16

Extensions with a fixed home, and typo safety

Teams can add their own fields in one place. Newer-version fields are tolerated; typos in known versions are rejected.

For the bank: x-bank-change-ticket: CHG-4821 rides along without breaking anything. A misspelt ignor: secrets/ is rejected, so an isolation boundary cannot silently disappear.

#142026-11-16

Version numbers checked exactly

Only valid versions of the current major are accepted.

For the bank: an instruction written for a future, incompatible format is refused, so an older system does not misread it.

#122026-11-15

An answer key for conformance

A public set of test cases with known correct answers, checked in CI on every change.

For the bank: procurement can test a vendor's agent tool against the answer key instead of trusting a conformance claim.

#112026-11-15

Rules mean what they say

MUST and SHOULD follow the IETF definitions, and the validation rules became binding.

For the bank: compliance can tell a violation from a recommendation without asking the author.

#3–#62026-11-15

Change control on ADP itself

A defect register, a proposal process, commit rules, hooks and CI. Nothing reaches main without a pull request and passing checks.

For the bank: the standard it relies on is itself under audited change control, with every decision traceable to a commit.

Next: ADP-1 highs

The 6 open high defects are all in ADP-1, the instruction format: whether SOURCE is a keyword, when a report may say COMPLETE, tier selection, schemas that reject envelopes no rule rejects, and a requirement stated as both MUST and SHOULD. They are the next work.

What ADP does not do yet

  • No validator implementation exists. Every check above is specified and tested on paper and in CI, not enforced in a running system.
  • ADP-1 and ADP-2 are Drafts. ADP-2's checks are now exact, but nothing has been built or used against them yet.
  • ADP gives an auditor structured evidence. It does not by itself make a firm compliant with any regulation.
